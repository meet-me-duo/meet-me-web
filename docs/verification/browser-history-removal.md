# 브라우저별 모임 주소 기록 제거

2026-10-29 사용자가 지정한 대상은 랜딩의 인터랙티브 설명 직전에 표시되던 ‘이 기기의 최근 모임’ 영역이다. 최신 운영 main `216730f676e16cb05d6f1758528d36ca46979296`에서 별도 `feature/remove-browser-room-history` 브랜치로 작업했다. 보류된 PR51/edit_guidance는 포함하지 않는다.

## 실제 제거 범위

- 랜딩의 전용 목록·바로가기와 RecentRooms 컴포넌트, useRecentRooms 구독, recentRooms 저장소 모듈을 제거했다.
- 방 생성/참여/조회 시 같은 주소 목록을 저장하던 호출과 해당 저장값으로 분기하던 이전 참여 안내를 제거했다. 방 하단의 계정 내 모임 안내는 유지하고 게스트에게 공유 URL 재진입을 안내한다.
- 목록 전용 스타일을 제거했다. 공유 링크 생성 함수는 저장 모듈에서 분리해 기존과 동일하게 유지했다.
- 예전 저장값을 읽거나 삭제하는 마이그레이션은 없다. 기존 사용자 저장값과 다른 저장 데이터는 그대로 두며 더 읽거나 쓰지 않는다.

## 유지한 경계

주최 생성 화면의 로그인 조건과 API 명세의 ‘로그인 계정으로 방과 주최자 참여 생성’/미로그인401을 확인했다. 인증 정책은 변경하지 않았다.

계정의 HOST/MEMBER 모임 목록·필터·보관 정책, credentials:include와 계정 Bearer, meet_me_guest HttpOnly 쿠키, 참가자 본인 확인·기록 재접근과 본인 입력 조회·수정은 기존 코드 그대로다. Web Storage의 주소 목록은 인증 수단이 아니며 제거 대상과 구분한다. 서버 모임·참가자·계정 데이터, 분석·모호성·결과·입력 확인 명령은 변경하지 않는다.

## 검증

- 전체 단위784/784(71파일), lint/typecheck/API 생성 정합/build/diff 검사 통과. 제거한7개 단위는 더 이상 제공하지 않는 로컬 주소 목록의 저장·정렬·30일 표시·삭제 테스트다. 기존 인증/분석/참가자 테스트는 보존했다.
- 대체 E2E12/12 통과. 최초 앱 로드 전부터 기존/손상 저장값을 심고 get/set/remove와 clear를 감시하며 접근0건·기존 값 및 별도 데이터 보존을 확인한다.
- 합성 HttpOnly 쿠키가 있는 익명 참여자의 공유URL 재방문, 원문 조회·명시적 수정, 수정 취소, 새로고침·뒤로가기·새 탭 재진입과 정리된 초대링크 복사를 검사한다. 명시적 수정 PUT 외 자동 쓰기 요청은 없다.
- 인증 없는 사용자는 기존 브라우저 metadata로 HOST/본인 권한을 얻지 못하고 생성도 로그인으로 차단된다. 저장소 사용을 막아도 계정의 생성·취소/뒤로가기와 Bearer가 필요한 서버 내 모임 조회는 유지된다.
- 최종 전체 브라우저 회귀509통과·기존skip1(로컬재시도0)을 확인했다. 정확 HEAD CI·게시/배포 상태는 해당 PR에 기록한다.
- 독립 검토에서 제거 범위·인증 경계·동일한 공유 링크 구현과 대체 테스트를 검토해 통과했다. 독립 관련 단위29/29도 통과했다. 권고에 따라 최초 앱 로드 전 저장소 감시와 계정 목록 Bearer 검증을 보강했다.

실제 계정 로그인/로그아웃·claim·방 생성/입력 수정/마감/삭제는 실행하지 않았다. 모든 동작 검사는 합성 API·쿠키·계정·모임만 사용했다. 로컬 시스템 Chromium의 최초 popup route 한계 때문에 OAuth 새 탭 검사만 loopback fixture를 사용하며 실제 공급자 인증과 구분한다.
